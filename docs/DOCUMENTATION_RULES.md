# 문서 및 대화 기록 규칙

## 목적

게임 규칙이 대화 중 사라지거나 코드와 설계가 어긋나지 않도록, 합의된 내용을 프로젝트 문서에 남깁니다.

## 문서 위치

- 강제해야 하는 개발 규칙: `AGENTS.md`
- 게임 설계: `docs/GAME_DESIGN.md`
- 화면 설계: `docs/UI_UX_SPEC.md`
- 데이터 규칙: `docs/DATA_SCHEMA.md`
- 구현 여부: `docs/IMPLEMENTATION_STATUS.md`
- 대화에서 합의된 사항: `docs/CHAT_HISTORY.md`
- 변경 요약: `docs/CHANGELOG.md`

## 갱신 시점

다음 중 하나가 발생하면 같은 작업 안에서 관련 문서를 갱신합니다.

1. 사용자가 새로운 기능이나 제한 조건을 확정했을 때
2. 기존 기능을 유지하거나 제외하기로 결정했을 때
3. 화면 흐름·데이터 구조·저장 규칙이 바뀌었을 때
4. 기능 상태가 구현, 부분 구현, 미구현 중 하나로 바뀌었을 때
5. 작업을 보류하거나 외부 확인이 필요한 항목이 생겼을 때

## 대화 기록 형식

`docs/CHAT_HISTORY.md`에는 모든 채팅 원문을 그대로 붙이지 않고 다음만 기록합니다.

- 날짜
- 요청 요약
- 확정된 결정
- 구현 또는 문서에 반영한 파일
- 보류·미해결 사항

새 기록은 파일 아래쪽에 추가하며, 기존 기록을 삭제하거나 과거 합의를 조용히 덮어쓰지 않습니다. 결정이 바뀌면 새 기록으로 변경 이유를 남깁니다.

## 작업 완료 규칙

작업을 마칠 때 응답과 함께 다음을 확인합니다.

- 코드 변경이 있으면 `IMPLEMENTATION_STATUS.md` 갱신 여부
- 설계 변경이 있으면 해당 설계 문서 갱신 여부
- 사용자와 결정한 내용이 있으면 `CHAT_HISTORY.md` 기록 여부
- 큰 변경이면 `CHANGELOG.md` 기록 여부
