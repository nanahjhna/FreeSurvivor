# 전체 화면 UI 배치 검토

## 검토 범위

2026-11-27 기준으로 모바일 세로 화면을 우선해 타이틀, 캐릭터 선택·생성, 마을 HUD, 지도·자동 이동, 캐릭터 정보·성장, 장비·대장간, 증강 카드 도감·상세, 내 스킬, 퀘스트, 던전 선택, 전투 HUD, 시작 증강 카드, 레벨업 증강 카드, 일시정지·설정, 전투 결과, 카드 던전 팝업을 코드 기준으로 검토했습니다.

이번 검토는 기능·저장 데이터·전투 규칙을 변경하지 않는 정적 배치 검토입니다. 이 세션에서는 Godot 실행 파일을 찾지 못해 새 런타임 캡처나 Android 실기기 터치 검증은 하지 않았습니다.

## 화면별 검토

### 1. 타이틀·캐릭터 선택·생성

타이틀은 세로 중앙의 제목과 동일 폭 세로 버튼 구조가 명확합니다. 승인 화면은 `ReferenceScreen`이 안전 영역 내부에서 552×940을 비율 유지해 축소하므로 기본 구조는 안정적입니다. 다만 최하단 `종료` 및 생성·삭제·피드백 영역은 기기 하단 제스처 영역과 실제로 겹치지 않는지 기기 확인이 필요합니다.

캐릭터 선택은 3개 슬롯 고정, 3D 프리뷰, 능력치와 생성·삭제 버튼의 정보 순서가 적절합니다. 긴 캐릭터명은 말줄임 처리가 있으나 승인 화면의 이름 영역은 단일 라벨이므로 긴 이름과 레벨이 함께 표시될 때 시각적 축약을 확인해야 합니다. 생성 화면은 직업 목록과 이름 입력, 생성 CTA가 모두 세로로 쌓이므로 키보드가 올라오는 상황에서 입력란·생성 버튼이 가려지는지 확인해야 합니다.

### 2. 마을 HUD·지도·자동 이동·퀘스트

마을 하단 메뉴는 좁은 폭에서 2열로 전환하고, 목표 카드와 자동 이동 버튼을 같은 하단 도크에 묶어 정보 흐름은 좋습니다. 지도와 자동 이동은 전체 딤 + 중앙 패널 구조이며 선택 목적지와 CTA가 분리되어 있습니다. 다만 실제 360×800 기기에서 목표 카드, 하단 메뉴, 가상 조이스틱의 세로 간격이 동시에 충분한지 확인해야 합니다.

퀘스트는 목록만 스크롤되고 상단 요약과 닫기 버튼은 고정되어 있어 적절합니다. 승인 퀘스트 화면도 목록 영역만 스크롤하도록 구성되어 있습니다. 수령 가능 카드의 제목·설명·진행바·보상 버튼이 긴 한글 문장에서 144px 최소 높이를 넘는 경우를 확인해야 하며, 넘을 경우 카드 높이를 내용 기반으로 늘리는 것이 우선입니다.

### 3. 캐릭터 정보·성장

캐릭터 정보는 3D 초상, 이름·레벨·EXP, 능력치·직업 효과 순서가 분명합니다. 성장 화면은 구매 전후 EXP와 구매 CTA가 하나의 패널에 모여 있어 목적이 명확합니다. 승인 성장 화면 하단 피드백 영역은 900~933 좌표에 있어 논리 화면 하단 여백이 좁으므로 긴 오류 문구가 두 줄 이상일 때 CTA와 겹치지 않는지 확인해야 합니다.

### 4. 장비 관리·대장간·증강 카드 도감·상세

장비 관리와 증강 카드를 동일 폭 2탭으로 묶은 것은 현재 화면 흐름에 맞습니다. 장비 화면은 중앙 3D 프리뷰, 네 슬롯, 보유 장비, 비교 패널, 추천 장착 순서가 적절하고 좁은 폭에서 슬롯 크기를 줄입니다. 증강 카드 도감은 목록과 상세를 별도 승인 화면으로 전환하며 상세 하단에 적용 대상 스킬과 피해 전후값을 두는 구조가 좋습니다.

정적 위험 요소는 카드 상세 텍스트의 정보 밀도입니다. 카드 이름·분류·등급·설명·적용 대상·계산 기준이 한 화면에 들어가므로 360×800에서는 설명과 적용 스킬 영역이 먼저 넘칠 수 있습니다. 상세 화면은 설명을 우선 3~4줄로 제한하고 나머지는 내부 세로 스크롤로 처리하는 방향이 안전합니다. 실제 카드 수가 많아질 때 도감 목록의 카드 최소 높이와 스크롤 포커스도 확인해야 합니다.

### 5. 내 스킬

실제 캐릭터 모델 프리뷰를 상단 30% 안팎으로 확보하고, 액티브 스킬 카드 가로 슬라이드와 Q/W/E/R 슬롯을 분리한 구조는 적절합니다. 승인 화면은 스킬명·쿨다운·계수·사거리·피해 공식·슬롯·CTA 순서가 명확합니다. 긴 스킬명과 피해 공식은 최대 2줄 제한이 있어 비교적 안전하지만, 패시브 설명과 하단 CTA 사이의 여백은 작은 화면에서 확인이 필요합니다.

### 6. 던전 선택·시작 증강 카드·레벨업 증강 카드

던전 선택은 탭 → 대표 이미지 → 목표·등장 적·보상·기록 → 입장 버튼 순서가 설계와 일치합니다. 대표 이미지 높이는 화면 비율에 따라 줄어들지만, 등장 적 목록이 길어지면 안내문이 입장 버튼을 밀어낼 수 있으므로 줄바꿈을 포함한 최소 높이 검증이 필요합니다.

레벨업과 시작 증강 카드는 공통 `level_up_panel.gd`를 사용하고, 좁은 폭에서 1열 카드와 내부 세로 스크롤로 전환합니다. 카드 분류·아이콘·이름·설명·현재 효과→적용 후 효과의 우선순위는 좋습니다. 다만 제목의 `습득` 안내가 길어지거나 카드 설명·적용 수치가 긴 경우, 카드 하나가 길어져 첫 화면에 카드 한 장만 보일 수 있습니다. 다음 수정 시에는 제목·부제목의 최대 줄 수, 카드 설명 최대 줄 수, 카드 간격을 함께 제한하고, 다시 뽑기 버튼이 보이는지 확인해야 합니다. 후보가 소진될 때 선택창을 닫고 전투를 재개하는 현재 흐름은 유지해야 합니다.

### 7. 전투 HUD

상단 상태, 중앙 전투 시야, 하단 조이스틱·스킬 슬롯을 분리한 방향은 적절합니다. 스킬 슬롯은 폭에 따라 축소되고 피해 숫자와 피해 유형을 별도 줄에 표시합니다. 실제 전투에서는 보스 표시·오프스크린 적 표시·카메라 줌·자동 시전 버튼이 동시에 나타날 수 있으므로 360×800에서 상단 요소가 서로 겹치지 않는지 우선 확인해야 합니다.

HUD 배치 편집기는 `_hud_editor.position = Vector2(16, 150)`, 최소 크기 300×420으로 고정되어 있습니다. 360×800에서는 세로 공간을 많이 차지하고 하단 버튼·조이스틱과 겹칠 수 있으며, 노치 상단 여백도 직접 반영하지 않습니다. 편집기를 열 때 안전 영역 기준 중앙 배치 또는 내부 스크롤 패널로 바꾸는 것이 P1 후속 항목입니다.

### 8. 일시정지·설정 팝업

일시정지는 재개·다시 시작·환경 설정·마을 복귀의 한 열 구조이며 재개 버튼이 강조되어 있어 좋습니다. 재시작·마을 복귀 확인 팝업도 공통 테마를 사용합니다.

환경 설정의 기본 세로 화면은 음량과 완료 버튼이 우선 노출되고 조작 설정은 접힌 상태라 정보 우선순위가 좋습니다. 그러나 조작 설정을 열면 `입력 모드` 행에 고정된 100px 라벨 + 220px OptionButton + 150px 초기화 버튼이 한 줄에 배치됩니다. 600px 미만 세로 화면에서 이 합계는 패널 내부 폭을 초과할 수 있어 버튼이 눌리거나 잘릴 가능성이 높습니다. P1 수정은 해당 행을 세로 또는 2행으로 바꾸는 것입니다. 키 목록 자체는 별도 내부 스크롤이라 방향은 적절합니다.

### 9. 전투 결과·카드 던전 팝업

전투 결과는 성공/실패, 생존 시간, 핵심 지표, 보상, 상세 전투 기록, 마을 복귀·다시 도전 순서가 분명합니다. 승인 결과 화면은 주요 CTA가 하단에 고정되어 있습니다. 기본 결과 화면의 보상 그리드는 `columns = 5`로 고정되어 있어 보상 아이템 이름을 직접 표시하거나 보상이 5종을 넘을 때 버튼 폭이 좁아집니다. 아이콘·수량 중심으로 유지하거나 세로 폭에 따라 3~5열로 전환하는 것이 안전합니다.

카드 던전은 현재 모바일 세로형 프로젝트 기준에서 가장 큰 배치 위험입니다. 적 HP 바에 최소 폭 700px, 결과·보상 오버레이에 620×360 고정 크기, 상단에 150px 포기 버튼과 130px 속도 선택이 지정되어 있습니다. 360~450px 폭에서는 적 패널·상단 컨트롤·팝업이 화면 밖으로 밀리거나 가로 스크롤을 유발할 가능성이 높습니다. 이 화면은 카드 손패만 가로 스크롤하는 구조로 유지하고, 나머지는 폭 비례·세로 스택·안전 영역 기반으로 재배치해야 합니다. 카드 던전이 현재 모바일 출시 범위에 포함된다면 P0으로 먼저 수정해야 합니다.

## 권장 후속 순서

1. 카드 던전의 고정 폭·고정 오버레이를 세로 반응형으로 수정합니다.
2. 환경 설정의 조작 설정 입력 모드를 좁은 폭에서 2행 또는 세로 스택으로 변경합니다.
3. HUD 배치 편집기를 안전 영역 중앙 패널 + 내부 스크롤 구조로 변경합니다.
4. 레벨업·시작 카드의 긴 문장에 최대 줄 수와 카드 높이 상한을 적용하고 360×800에서 첫 카드·다시 뽑기·CTA 노출을 확인합니다.
5. 전투 결과 보상 그리드를 폭에 따라 3~5열로 조정합니다.
6. 위 변경 후 360×800, 390×844, 450×800, 720×1280에서 팝업 열기·닫기·스크롤·하단 CTA 터치를 재검증합니다.

## 검증 제한

- 이번 검토는 코드와 기존 문서 기준입니다.
- 이 세션에서는 Godot 실행 파일이 PATH에 없어 새 headless 실행과 화면 캡처를 수행하지 못했습니다.
- Android 노치·하단 제스처 영역·실제 손가락 터치 간격은 아직 미확인입니다.
- 저장 데이터, 캐릭터 데이터, 전투 규칙, 증강 적용 규칙은 변경하지 않았습니다.
