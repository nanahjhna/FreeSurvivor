# 데이터 구조 규칙

## 캐릭터

- 중심 리소스: `data/characters/charNN.tres`
- 타입: `CharacterData`
- 포함 정보: 고유 ID, 이름, 직업, 모델, 기본 능력치, 애니메이션, 스킬, 무기, 장비
- 검색: `CharacterRegistry`

캐릭터 추가 시 여러 스크립트에 ID를 복사해 하드코딩하지 않고 리소스 검색 결과로 UI 목록을 생성합니다.

### 영구 성장 상태

캐릭터별 저장 상태(`GameData.characters[char_id]`)에는 다음 진행 값을 사용합니다.

- `level`: 전투와 분리된 영구 캐릭터 총 레벨(기본 1)
- `character_xp`: 현재 영구 경험치
- `character_xp_to_next`: 다음 캐릭터 레벨에 필요한 경험치
- `growth_level`: 이전 저장과의 호환을 위한 내부 값이며 `level - 1`로 정규화
- `attributes`: 레벨업으로 적용된 실제 능력치

여관에서 구매한 경험치는 `character_xp`에만 더해지고, 필요 EXP를 넘을 때만 레벨과 능력치가 함께 증가합니다. 전투의 `player_level`, `player_current_xp`, `player_xp_to_next`는 별도 런타임 상태입니다.

## 스킬

- 캐릭터별 스킬은 가능한 한 `CharacterData.skills`에 연결합니다.
- 공통 스킬과 효과는 기존 스킬 데이터베이스 및 매니저를 재사용합니다.
- 레벨업 선택지는 실제 등록된 스킬만 표시합니다.

## 몬스터와 던전

- 몬스터 리소스는 `data/monsters/monsterNN.tres`를 기준으로 관리합니다.
- 던전 UI에 표시하는 몬스터·보스·보상·난이도는 실제 데이터와 연결합니다.
- 별도 던전 데이터가 없는 항목은 미구현으로 표시하고 가상 데이터를 만들지 않습니다.

## 아이템과 장비

- 아이템 ID, 등급, 스탯, 수량, 장착 위치, 강화 단계는 저장 가능한 데이터로 관리합니다. 장비 위치에는 `weapon`, `armor`, `accessory`, `boots`(신발)가 포함됩니다.
- 상세 팝업은 선택된 실제 아이템을 기준으로 표시합니다.
- 장비 계산 결과와 화면에 표시되는 능력치는 동일한 원천 데이터를 사용합니다.

## 저장 호환성

- 기존 `legacy_id`, 저장 슬롯, 장비·스킬 데이터를 우선 보존합니다.
- 필드 변경이 필요하면 기본값과 이전 버전 변환 방식을 먼저 정의합니다.
- 기존 저장 데이터를 삭제하거나 특정 캐릭터로 일괄 변경하지 않습니다.
