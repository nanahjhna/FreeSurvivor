# Android AAB 빌드 규칙

이 문서는 FreeSurvivor의 Android 출시 번들을 만들 때 반복해서 적용하는 규칙입니다. 목적은 기존 게임 기능과 저장 데이터를 보존하면서 AAB 용량을 줄이고, 어떤 파일이 실제로 배포되는지 확인 가능하게 만드는 것입니다.

## 기본 출력과 프리셋

- Godot의 `Android` 프리셋을 사용합니다.
- 출력은 `build/FreeSurvivor-{version-name}-optimized.aab` 형식을 사용합니다. 현재 기준 출력은 `build/FreeSurvivor-2.1-optimized.aab`입니다.
- `gradle_build/export_format=1`로 AAB 형식을 유지합니다.
- 출시 서명(`package/signed=true`)을 유지합니다. 서명 파일과 비밀값은 문서나 저장소에 기록하지 않습니다.
- `armeabi-v7a`와 `arm64-v8a`를 기본 포함합니다.
- x86·x86_64는 별도 요구가 없으면 포함하지 않습니다.
- `version/name`과 `version/code`는 빌드 전에 확인하고, 직전 AAB보다 반드시 높은 값을 사용합니다. 둘 중 하나라도 직전 값 이하이면 빌드를 진행하지 않습니다.
- 직전 AAB의 버전명과 버전 코드는 파일명, 빌드 기록 또는 AAB Manifest에서 확인합니다. 확인할 기준이 없으면 먼저 기준 빌드를 정합니다.
- 최소 SDK·대상 SDK가 프리셋에 비어 있으면 Godot/Gradle 기본값을 사용하는 상태로 보고하며, 값을 변경할 때는 변경 이유와 결과를 기록합니다.

## 빌드 전 확인

1. `AGENTS.md`와 이 문서를 먼저 읽습니다.
2. `export_presets.cfg`의 Android 프리셋, 출력 경로, 버전, ABI, 서명 상태를 확인합니다.
3. 직전 AAB와 비교해 버전명과 버전 코드가 모두 증가했는지 확인합니다. 증가하지 않았으면 `export_presets.cfg`를 먼저 갱신합니다.
4. Android SDK, build-tools, platform-tools, JDK, Godot export template이 준비되어 있는지 확인합니다.
5. 기존 AAB가 있으면 보존하고, 최적화 번들은 별도 파일로 생성합니다. 기존 번들을 덮어쓰거나 삭제하지 않습니다.
6. 사용 중인 캐릭터·스킬·NPC·스테이지 리소스를 임의로 제외하지 않습니다. 개발 전용 도구만 export preset의 제외 필터로 제거합니다.

## 용량 최적화 규칙

### 텍스처

- 원본 PNG와 캐릭터 원본 에셋은 보존합니다.
- 가져오기 설정에서 마을·자연·몬스터 텍스처는 최대 1024px를 기본 상한으로 사용합니다.
- 환경 보조 텍스처와 NPC 보조 텍스처처럼 화면 영향이 작은 리소스는 최대 512px까지 낮출 수 있습니다.
- 임포트 설정만 조정하고 원본 이미지를 재생성하거나 삭제하지 않습니다.
- 텍스처 압축 변경 후 AAB 안의 실제 파일 크기를 확인합니다.

### 애니메이션 GLB

- 원본 GLB, 스켈레톤, `Rest_Pose`, `RESET`과 실제 `CharacterData`에서 사용하는 클립은 보존합니다.
- 임포트 단계에서 단일 뼈의 회전 트랙과 `mixamorigHips` 위치 트랙을 우선 유지합니다.
- 사용하지 않는 스케일·속성·불필요한 위치·루트 이동 트랙은 제거할 수 있습니다. 캐릭터 이동은 컨트롤러가 담당하므로 걷기·달리기의 수평 루트 이동을 중복 적용하지 않습니다.
- `Animation.optimize`로 허용 오차 안에서 반복 키를 줄이고, `Animation.compress`로 키 데이터를 압축합니다.
- 실제 사용하는 클립을 확인하지 않고 전체 동작 목록을 삭제하지 않습니다.
- 런타임 리타게팅이 필요한 경우 압축된 원본을 공유 캐시하고, 필요한 클립만 복사해 기존 리타게팅 경로에 연결합니다.
- 최적화만으로 애니메이션의 시각적 품질이 검증되었다고 기록하지 않습니다. 화면·기기 확인을 하지 않았다면 미확인으로 남깁니다.

## 빌드 후 확인

- 출력 AAB가 존재하고 파일 크기를 기록합니다.
- ZIP 내부의 `AndroidManifest.xml`에서 패키지명, 버전명, 버전 코드를 확인합니다.
- 직전 AAB와 비교해 새 AAB의 버전명과 버전 코드가 모두 높은지 다시 확인합니다.
- `jarsigner -verify` 또는 동등한 방법으로 출시 서명을 확인합니다.
- 최적화 전후 용량과 주요 감소 원인(텍스처, 애니메이션, 개발 리소스)을 기록합니다.
- AAB 생성·서명·구조 확인과 게임 실행 검증을 구분합니다. Android 기기 실행, 화면 배치, 입력, 애니메이션 시각 확인을 하지 않았다면 완료된 것처럼 보고하지 않습니다.
- 빌드 실패 시 원본 에셋이나 저장 데이터를 삭제하지 않고, 오류와 재현 조건을 기록합니다.

## 문서 기록

- 빌드 설정이나 최적화 정책을 바꾸면 `docs/CHANGELOG.md`에 요약합니다.
- 사용자와 버전, 출력 경로, 용량 목표를 확정하면 `docs/CHAT_HISTORY.md`에 결정사항을 남깁니다.
- 실제 구현 상태가 바뀐 경우에만 `docs/IMPLEMENTATION_STATUS.md`를 갱신합니다.
- 각 AAB의 버전명, 버전 코드, 출력 경로, 파일 크기, 서명 확인 여부를 작업 결과에 함께 보고합니다.
